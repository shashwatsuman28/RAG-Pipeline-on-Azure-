# Documentio Technical Research

**Status**: Verified against cited official documentation on 2026-11-02; no cloud resources, SDK calls, benchmarks, or deployments were run. Regional service/model availability and subscription quota must be rechecked when those inputs are known.

## Findings and Proposed Directions

| Topic | Research conclusion | Proposed direction / status |
|---|---|---|
| Azure service naming | Current Microsoft Learn pages use Azure AI Search, Azure Document Intelligence in Foundry Tools, Azure Databricks, Azure OpenAI in Microsoft Foundry Models, and Microsoft Entra ID. Product naming continues to evolve. | Use current service names and revalidate names/API references during implementation. |
| Document Intelligence API and SDK | REST API v4.0 `2024-11-30` is GA and current. The SDK pairing table lists Python SDK `azure-ai-documentintelligence` 1.0.0 for v4.0; PyPI lists 1.0.2 on the access date. Layout extracts text, structure, and tables; PDF, images, DOCX, Excel, PPTX/HTML support is model/feature dependent. v4 layout does not imply arbitrary key-value extraction. Office embedded images are not analyzed. Official v4 pages conflict on Excel extensions (XLS vs XLSX), and the XLSX table limitation must be verified for the exact API/model. | Evaluate v4 layout for general extraction and appropriate prebuilt/custom models only when document type and field needs are defined. Build a format-feature fixture matrix; confirm Excel extension support directly before promising it. Do not promise universal table/key-value/layout extraction. |
| Document Intelligence limits and billing | Current docs list S0 max input size 500 MB, up to 2,000 PDF/TIFF pages; F0 is 4 MB and first two pages. Office character/page accounting and quotas differ. Billing is per analyzed page/model. | Decide supported limits from representative corpus, region, tier, and budget. Never encode the example quotas as Documentio limits without approval. |
| Azure SDK authentication | Azure SDKs use Azure Identity and support `DefaultAzureCredential`; Document Intelligence v4 Python supports Entra token credentials, but regional endpoints do not support Entra ID and a custom subdomain is required. Blob supports Entra ID and recommends managed identity where possible. | Prefer managed identity for Azure-hosted service-to-service access, subject to resource support and role scoping. Confirm endpoint/subdomain and local developer auth per environment. |
| Python Azure SDKs | Official SDK docs identify `azure-storage-blob` (current page requires Python 3.10+) and `azure-search-documents` as the Python packages for Blob and Azure AI Search. Search clients support `DefaultAzureCredential`/Entra RBAC for search, index, and indexer clients. | Candidate dependency set is `azure-identity`, `azure-storage-blob`, `azure-ai-documentintelligence`, and `azure-search-documents`; choose a Python runtime meeting the strictest verified dependency and selected Databricks/LangChain requirements, then lock exact compatible versions. |
| Databricks storage access | Unity Catalog supports managed identities via an Azure Databricks Access Connector, storage credentials, and external locations. ADLS Gen2 external locations require hierarchical namespace. Databricks docs recommend Unity Catalog governance; do not default to legacy DBFS mounts. | If Databricks remains selected, evaluate ADLS Gen2 + Unity Catalog external locations and scoped identity; network, region, lifecycle, cost, and permissions require design validation. |
| Incremental processing | Databricks Auto Loader tracks discovered files in checkpoints and documents exactly-once semantics for supported writes to Delta Lake; file discovery/processing may be out of order. This does not guarantee exactly-once downstream effects in Azure AI Search. Lakeflow pipelines are the current naming for Spark Declarative Pipelines. Blob Event Grid is at-least-once and can duplicate/reorder events; Blob change feed is ordered per blob and durable but delayed by minutes, and its documented support conditions must be checked against ADLS Gen2. | Use notifications only as triggers. Make source revision and processing idempotency keys authoritative; reconcile from source state and durable checkpoints, including Search side effects. Event mechanism remains undecided. |
| Azure AI Search vectors | Vector fields use `Collection(Edm.Single)`, configured dimensions must equal model output, and vector fields are searchable but not filterable/facetable/sortable. Current service docs allow up to 4,096 dimensions; `text-embedding-3-large` supports up to 3,072 and ada-002 is fixed at 1,536. | Use one versioned embedding space per field; keep dimension/model as an ADR pending benchmark and cost review. Do not set index schema dimensions until the model is approved. |
| Hybrid retrieval and ranking | Azure AI Search runs BM25 full-text and vector queries together, merges with Reciprocal Rank Fusion (RRF), and supports filters. Semantic ranker optionally reranks the top result set, works on text, and has region, throughput, and pricing constraints. | Candidate pipeline: authorization filter + hybrid lexical/vector retrieval; benchmark semantic ranking as an optional stage, not a required assumed capability. |
| Search authorization | A string security filter is a generally available filter pattern but does not authenticate/authorize the supplied principal. Native ACL/RBAC, Purview, and SharePoint token-based query enforcement are documented as preview in current pages. | Require trusted caller identity and authorization data provenance. Do not assume preview features for production. Decide permission authority and synchronization; test filter bypass, stale ACL, cache, citations, and answer leakage. |
| Embedding candidates | Microsoft model catalog lists `text-embedding-ada-002` at 1,536 dimensions and `text-embedding-3-large` up to 3,072; third-generation embeddings accept dimensions reduction and require re-embedding when changing model. The current model catalog is date/region/deployment-sensitive. | Benchmark recall/quality and total storage/inference cost on a representative corpus before selection. Rebuilding the vector index is expected when changing embedding spaces. |
| Chat model candidate | GPT-4o appears in Microsoft’s Foundry model documentation; availability, version lifecycle, deployment type, region, quotas, and pricing depend on current catalog and deployment configuration. | Treat GPT-4o as a candidate only. Compare supported GA models at selection time and pin deployment/model version policy. |
| Azure OpenAI API and Python | The Azure OpenAI v1 API is GA (August 2025) and removes dated `api-version` parameters for supported v1 operations. Microsoft docs show the OpenAI Python client with `DefaultAzureCredential` token provider and deployment name. Microsoft SDK examples use scope `https://ai.azure.com/.default`; the LangChain Azure guide uses `https://cognitiveservices.azure.com/.default`. LangChain documents `langchain-openai`, `ChatOpenAI` with Azure v1 endpoint, and `AzureChatOpenAI` for traditional API-versioned calls. | Prefer v1-compatible client path after verifying selected model capability and token audience for the selected client/endpoint. Avoid hard-coding a token scope from another client example. Exact LangChain integration remains a package/version decision. |
| LangChain Search integration | The current LangChain docs endpoint for the Azure Search vector store returned 404 in this research tool; a prior canonical path redirected to `docs.langchain.com/oss/python/integrations/vectorstores/azuresearch` but was not retrievable. | Mark exact integration class/package/hybrid option as unresolved. Before implementation, validate active LangChain docs, package release, Azure SDK compatibility, and use an adapter boundary. Do not choose an obsolete chain by memory. |
| Conversation context | Current LangChain short-term memory guidance uses state per thread and a checkpointer for persistence; in-memory saver is for examples, and production guidance uses persistent checkpointers. History trimming/summarization is a policy choice. | Keep identity-bound conversation state behind an explicit interface. Database, expiry, encryption, retention, deletion, and summarization policy remain open. No chain class is selected. |
| App Service vs AKS | Microsoft describes App Service as managed web/API hosting with lower operations burden. AKS Automatic offers more managed node provisioning, scaling, security defaults, monitoring, and upgrades; AKS Standard provides more configuration control and operator responsibilities. Both need workload/network/region/cost fit validation. | No host selected. Compare App Service and AKS Automatic/Standard after throughput, deployment, network, scaling, background-work, and team-skill inputs are approved. |
| Evaluation | Search ranking, answer grounding, citation correctness, authorization isolation, and resilience are distinct validation dimensions. | Create versioned query/corpus datasets and evaluate retrieval and generation separately; owner-approved thresholds required before implementation exit criteria. |
| Operations telemetry | Azure Monitor collects metrics, logs, traces, and events; Databricks Lakeflow pipeline UI/event log/query history can report update status, data quality, lineage, streaming metrics, and resource use. | Select telemetry integration and retention only after host/Databricks and data policy decisions; telemetry must be redacted and owner-operated. |

## Key Decisions Still Open

1. Authoritative document permission source and synchronization method; native Search options include preview features.
2. Corpus formats beyond PDF/Word and exact file/page/character limits; extraction features differ by model and Office type.
3. Whether real enterprise data will be used in the portfolio project; classification, residency, retention, deletion, and compliance scope.
4. Azure region, model deployments, quotas, budget, and private networking.
5. Hosting choice and feasibility of 1,000 concurrent / 50,000 total users.
6. Embedding model/dimensions, chat model, search tier/index schema, LangChain package path, conversation store, and user client.
